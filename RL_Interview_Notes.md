## WHAT MAKES RL DIFFERENT

| | Supervised | Unsupervised | Reinforcement |
|---|---|---|---|
| Signal | correct label `y` | none | scalar reward, often delayed |
| Data | i.i.d., fixed | i.i.d., fixed | **generated by your own policy** |
| Feedback | instructive ("the answer was 7") | — | evaluative ("that was worth 3") |
| Goal | minimize prediction error | find structure | maximize expected return |

Four problems that exist only here:
1. **Credit assignment** — which of the last 200 actions caused this reward?
2. **Exploration vs exploitation** — you only learn about actions you take.
3. **Non-stationarity** — improving the policy changes the data distribution.
4. **Bootstrapping instability** — learning targets built from your own current (wrong) estimates.

**The 5 questions behind every RL interview question:** What's the MDP (states, actions, reward, γ)? Is the method **model-based or model-free**? **On-policy or off-policy**? **Value-based, policy-based, or both**? Does it **bootstrap**, and if so what keeps it stable?

# PART 0 — CHEAT SHEET

```
RETURN            G_t = r_(t+1) + gamma r_(t+2) + ... = sum_k gamma^k r_(t+k+1)
STATE VALUE       V^pi(s)   = E_pi[ G_t | s_t = s ]
ACTION VALUE      Q^pi(s,a) = E_pi[ G_t | s_t = s, a_t = a ]
ADVANTAGE         A^pi(s,a) = Q^pi(s,a) - V^pi(s)

BELLMAN EXPECTATION
  V^pi(s)   = sum_a pi(a|s) sum_s' P(s'|s,a)[ R + gamma V^pi(s') ]
  Q^pi(s,a) = sum_s' P(s'|s,a)[ R + gamma sum_a' pi(a'|s') Q^pi(s',a') ]

BELLMAN OPTIMALITY
  V*(s)   = max_a sum_s' P(s'|s,a)[ R + gamma V*(s') ]
  Q*(s,a) = sum_s' P(s'|s,a)[ R + gamma max_a' Q*(s',a') ]
  pi*(s)  = argmax_a Q*(s,a)

UPDATE RULES (all are "estimate <- estimate + alpha [ target - estimate ]")
  MC              V(s)   += a [ G_t              - V(s)   ]
  TD(0)           V(s)   += a [ r + g V(s')      - V(s)   ]
  n-step          V(s)   += a [ G_t:t+n          - V(s)   ]
  SARSA           Q(s,a) += a [ r + g Q(s',a')   - Q(s,a) ]     ON-policy
  Expected SARSA  Q(s,a) += a [ r + g E_a'[Q]    - Q(s,a) ]
  Q-learning      Q(s,a) += a [ r + g max Q(s',.) - Q(s,a) ]    OFF-policy
  Double Q        a*=argmax Q_A(s',.) ; target = r + g Q_B(s',a*)

POLICY GRADIENT
  grad J = E[ grad log pi(a|s) * Psi ]
  Psi choices (increasing bias, decreasing variance):
      G_t                         REINFORCE
      G_t - b(s)                  REINFORCE with baseline
      Q(s,a)                      actor-critic
      A(s,a) = Q - V              advantage actor-critic
      r + gamma V(s') - V(s)      TD error (one-step advantage)
      GAE(gamma, lambda)          the modern default

TAXONOMY
                model-free ------------------- model-based
  value-based:  Q-learning, SARSA, DQN         Dyna-Q, MCTS, MuZero
  policy-based: REINFORCE, PPO, TRPO           world models, Dreamer
  both (AC):    A2C/A3C, SAC, TD3, DDPG
```

**Which algorithm when:**

| Situation | Use |
|---|---|
| Small discrete state & action space | Tabular Q-learning / SARSA |
| Continuous state, discrete actions | DQN family, or PPO |
| Continuous actions | SAC, TD3, DDPG, PPO |
| Environment steps are expensive | Model-based (Dyna, MBPO), offline RL |
| Only logged data, no interaction | Offline RL (CQL, IQL, BC) |
| Need stability above all | PPO |
| Sample efficiency matters most | SAC (off-policy + replay) |
| Fine-tuning an LLM on preferences | PPO (RLHF) or DPO (no RL loop) |

# PART 1 — THE MDP FRAMEWORK

## 1.1 Definition
```
MDP = (S, A, P, R, gamma)
  P(s'|s,a)  transition dynamics
  R(s,a,s')  reward function
  gamma      discount in [0,1]
```
**Markov property:** `P(s_(t+1) | s_t, a_t) = P(s_(t+1) | s_1..s_t, a_1..a_t)`. The state summarizes everything relevant from the history. If it doesn't, you have a **POMDP** and need memory (frame stacking, an RNN, or a belief state).

**Why discount?**
- Mathematically: guarantees the infinite sum converges (`|G| <= r_max/(1−γ)`).
- Modelling: future reward is less certain / less valuable.
- Practically: γ sets the **effective horizon** ≈ `1/(1−γ)`. γ=0.99 → ~100 steps. Too low is myopic; too high raises variance and slows convergence.

**Reward design.** The reward defines the task, and agents optimize what you *wrote*, not what you *meant* — reward hacking. Prefer sparse-but-correct to dense-but-gameable. **Potential-based shaping** `F = γΦ(s') − Φ(s)` is the only form provably guaranteed not to change the optimal policy.

## 1.2 Policies and values
```
policy       pi(a|s)  — stochastic, or deterministic pi(s)
V^pi(s)      expected return from s following pi
Q^pi(s,a)    expected return taking a in s, then following pi
A^pi(s,a)    Q - V, "how much better than average is this action"
```
Every finite MDP has at least one **deterministic optimal policy**. Stochastic policies are still needed for exploration, for POMDPs, and for games with mixed-strategy equilibria.

## 1.3 The Bellman equations
Everything in RL is a way of solving or approximating these. The key mathematical fact:

```
The Bellman operator T is a gamma-CONTRACTION in the max norm:
    || T V - T U ||_inf  <=  gamma || V - U ||_inf
```
By Banach's fixed-point theorem there is a **unique** fixed point (V* or V^π) and iterating from **any** starting point converges to it geometrically at rate γ. That single fact justifies value iteration, policy evaluation, and (with stochastic approximation) Q-learning.

# PART 2 — DYNAMIC PROGRAMMING (the model is known)

```
POLICY EVALUATION    sweep V(s) <- sum_a pi(a|s) sum_s' P[R + gamma V(s')]
POLICY IMPROVEMENT   pi'(s) <- argmax_a sum_s' P[R + gamma V(s')]
POLICY ITERATION     alternate the two until the policy stops changing
VALUE ITERATION      V(s) <- max_a sum_s' P[R + gamma V(s')]   (fused, one sweep)
```

**Policy improvement theorem:** if `Q^π(s, π'(s)) ≥ V^π(s)` for all s, then `V^π' ≥ V^π` everywhere. Greedy improvement satisfies this by construction, so policy iteration improves monotonically and terminates (finitely many deterministic policies).

**Generalized Policy Iteration (GPI)** is the organizing idea of the whole field: *any* interleaving of (partial) evaluation and (partial) improvement converges. Value iteration, SARSA, Q-learning, and actor-critic are all GPI with different approximations.

```
cost per sweep   O(|S|^2 |A|)
policy iteration few iterations, each expensive
value iteration  many iterations, each cheap
```

**Limits:** requires the full model `P`, and `|S|` grows exponentially with the number of state variables (Bellman's own phrase, the *curse of dimensionality*). Everything after this part exists to remove one of those two requirements.

In the companion code, on a 5×4 gridworld: policy iteration converges in 4 policy improvements, value iteration in 5 sweeps, and they agree on every state.

# PART 3 — MODEL-FREE PREDICTION

## 3.1 Monte Carlo
```
G_t = actual return observed after visiting s
V(s) <- V(s) + alpha [ G_t - V(s) ]        (or a running average)
```
- **Unbiased**, since `G_t` is a true sample of `V^π(s)`.
- **High variance** — the return depends on every random choice for the rest of the episode.
- Requires **episodic** tasks; no updates until termination.
- **No bootstrapping**, so it is unaffected by a bad initial V and converges even with function approximation where TD might not.
- First-visit (i.i.d. samples, clean theory) vs every-visit (biased for finite data, consistent).

## 3.2 Temporal difference — the central idea
```
V(s_t) <- V(s_t) + alpha [ r + gamma V(s_(t+1)) - V(s_t) ]
                            |------ TD target -----|
                            |--------- TD error (delta) -------|
```
**Bootstrapping**: update a guess toward a better guess. Consequences:
- Learns **online**, after every step; works on **continuing** tasks.
- **Biased** (V(s') is currently wrong) but **much lower variance** (one reward, one transition).
- Converges to the **maximum-likelihood MDP** solution given the data, whereas MC converges to the minimum-MSE fit of the observed returns. On the classic random walk, TD reaches a lower error and tolerates far larger step sizes.

Measured in the companion code (7-state random walk, 500 episodes, 15 seeds), RMSE vs the exact values:

| α | MC | TD(0) | n=3 | TD(0.8) |
|---|---|---|---|---|
| 0.02 | 0.0442 | 0.0484 | **0.0385** | 0.0451 |
| 0.05 | 0.0716 | **0.0409** | 0.0616 | 0.0698 |
| 0.1 | 0.0937 | 0.0565 | 0.0802 | 0.0905 |
| 0.2 | 0.1310 | 0.0748 | 0.1045 | 0.1333 |
| 0.4 | 0.2049 | 0.1147 | 0.1706 | 0.2295 |

TD's best beats MC's best, and TD degrades far more gracefully as α grows — that is the variance difference made concrete.

## 3.3 n-step and TD(λ)
```
G_t:t+n = r_(t+1) + ... + gamma^(n-1) r_(t+n) + gamma^n V(s_(t+n))
    n = 1  -> TD(0) ;   n = inf -> Monte Carlo ;  intermediate n usually best

lambda-return   G_t^lam = (1-lam) sum_{n>=1} lam^(n-1) G_t:t+n

BACKWARD VIEW (eligibility traces), computed online:
    e(s) <- gamma*lam*e(s) + 1{s = s_t}
    delta = r + gamma V(s') - V(s)
    V(s) <- V(s) + alpha * delta * e(s)     for ALL s
```
The trace is a short-term memory of how **recently** and how **often** each state was visited — i.e. how much credit it deserves for the current TD error. λ=0 gives TD(0); λ=1 gives Monte Carlo. This is the bias-variance dial of RL.

# PART 4 — MODEL-FREE CONTROL (tabular)

## 4.1 On-policy vs off-policy — the distinction to nail
```
ON-POLICY   learn about the policy you are FOLLOWING
            SARSA, Expected SARSA, REINFORCE, A2C, PPO
OFF-POLICY  learn about a TARGET policy while following a different BEHAVIOUR
            policy.  Q-learning, DQN, SAC, TD3, offline RL
```
Off-policy is strictly more powerful — it enables replay buffers, learning from demonstrations or logs, and learning many policies at once — but it is less stable, and combined with bootstrapping and function approximation it can diverge (the deadly triad, Part 5).

```
SARSA        Q(s,a) += a[ r + g Q(s',a') - Q(s,a) ]     a' = action ACTUALLY taken
Q-learning   Q(s,a) += a[ r + g max Q(s',.) - Q(s,a) ]  max = GREEDY, whatever you did
Expected     Q(s,a) += a[ r + g sum_a' pi(a'|s')Q(s',a') - Q(s,a) ]
```
**Expected SARSA** removes the variance from sampling a', tolerates much larger α, and is never worse than SARSA. With a greedy target policy the expectation *becomes* the max — so Expected SARSA generalizes Q-learning.

## 4.2 The cliff — the canonical demonstration
Measured in the companion code (constant ε = 0.1, 500 episodes):

| Algorithm | Online return | Greedy policy return |
|---|---|---|
| SARSA (on-policy) | **−14.28** | −10.00 |
| Expected SARSA | −14.86 | −8.00 |
| Q-learning (off-policy) | −23.22 | **−6.00** |
| Double Q-learning | −22.01 | **−6.00** |

Q-learning's *greedy* policy is optimal — the short path hugging the cliff edge — but its *online* return is worse, because ε-greedy exploration keeps pushing it over. SARSA backs up the action it actually takes, so it accounts for its own randomness and learns the safer route one row up.

**The moral:** off-policy learns the optimal policy; on-policy learns the best policy *given that you are still exploring*. Which you want depends on whether mistakes during learning are cheap (simulator) or catastrophic (a real robot).

## 4.3 Maximization bias and Double Q-learning
```
E[ max_a Qhat(s,a) ] >= max_a E[ Qhat(s,a) ]      (Jensen)
```
Taking a max over **noisy** estimates systematically overestimates, because whichever action happens to have positive noise gets selected. Fix by decoupling selection from evaluation:
```
a*     = argmax_a Q_A(s', a)          select with A
target = r + gamma * Q_B(s', a*)      evaluate with B
```
Q_B's noise on `a*` is independent of the argmax, so the bias cancels. Scaled up, this is Double DQN.

## 4.4 Convergence conditions
```
Q-learning converges to Q* w.p. 1 if:
  1. every (s,a) is visited infinitely often
  2. Robbins-Monro step sizes:  sum alpha_t = inf ,  sum alpha_t^2 < inf
GLIE for control: Greedy in the Limit with Infinite Exploration
  (e.g. eps_k = 1/k satisfies both conditions)
```

## 4.5 Exploration
```
eps-greedy      simple, undirected; linear regret unless decayed
optimistic init set Q above any achievable value -> every untried action looks
                good, so the agent explores systematically with eps = 0.
                Free and powerful in stationary tasks; useless in
                non-stationary ones (the optimism is spent once)
UCB             mu_a + c sqrt(ln t / n_a) — optimism with a shrinking bonus
Thompson        sample from the posterior, act greedily on the sample
Boltzmann       pi(a) proportional to exp(Q(s,a)/tau)
entropy bonus   add beta*H(pi) to the objective (policy-gradient methods)
count-based     intrinsic reward ~ 1/sqrt(N(s)), or pseudo-counts for large S
curiosity       intrinsic reward = prediction error of a learned dynamics model
```
Measured in the companion code (10×5 maze, 400 episodes, Q-learning):

| Q init | ε | Greedy return | Outcome |
|---|---|---|---|
| pessimistic | 0.0 | −3.000 | never found the goal |
| pessimistic | 0.1 | −3.000 | never found the goal |
| pessimistic | 0.3 | 0.800 | found the goal |
| pessimistic | 0.5 | −3.000 | never found the goal |
| optimistic | 0.0 | **0.800** | found the goal |

Two lessons. Pure exploitation from a pessimistic start never finds the goal. And **ε-greedy barely helps** — undirected random walking has to stumble onto reward, and that probability decays exponentially with distance. This is the **hard-exploration problem** (Montezuma's Revenge is the famous case), and it is why count-based bonuses, curiosity, and Go-Explore exist.

## 4.6 Dyna-Q — planning with a learned model
```
after each REAL step:
  1. normal Q-learning update on the real transition
  2. store it:  Model[(s,a)] = (r, s')
  3. do n extra Q-learning updates on transitions SAMPLED from the model
```
Planning and learning become the *same update* applied to imagined vs real data. Measured in the companion code (10×5 maze, 30 episodes), real environment steps consumed:

| | Real steps used | Final policy |
|---|---|---|
| Plain Q-learning | 3,458 | 0.800 |
| Dyna-Q, 5 planning steps | 1,286 | 0.800 |
| Dyna-Q, 30 planning steps | **938** | 0.800 |

Same policy, ~3.7× fewer environment interactions. That trade matters whenever steps are expensive (robots, clinical trials) rather than free (simulators). The risk is **model bias** — plan confidently on a wrong model and you optimize fiction. Dyna-Q+ adds exploration bonuses for stale transitions to cope with a changing world.

# PART 5 — FUNCTION APPROXIMATION

## 5.1 Why
A table needs one entry per state. CartPole has 4 continuous variables; Go has 10^170 positions; pixels are worse. We need `Q(s,a;w)` that **generalizes** across similar states.

```
Linear         Q(s,a) = w_a . x(s)            features x: tile coding, RBF, polynomial
Neural         Q(s,a) = NN(s; w)[a]           learned features
Semi-gradient  w += alpha [ target - Q(s,a;w) ] grad_w Q(s,a;w)
```
It's called **semi**-gradient because we differentiate only `Q(s,a;w)`, treating the target `r + γ max Q(s',·;w)` as a constant even though it also depends on w. The true (residual) gradient is slower and usually worse in practice.

**Tile coding**: overlay `n` offset grids; a state activates exactly one tile per tiling, giving a sparse binary feature vector. Generalization is local and controllable, updates are cheap, and linear convergence theory still applies. Measured in the companion code: 8 tilings × 8⁴ tiles with semi-gradient SARSA takes CartPole from 9.2 to **198.2** steps (max 200).

## 5.2 The deadly triad
```
DIVERGENCE is possible when ALL THREE are present:
   1. function approximation
   2. bootstrapping
   3. off-policy training
```
Any two are safe. On-policy semi-gradient SARSA (1+2) is fine. Monte Carlo with approximation (1+3) is fine. Tabular Q-learning (2+3) is fine. Baird's counterexample shows linear off-policy TD diverging to infinity. This is exactly the corner DQN lives in, which is why it needs specific stabilizers.

## 5.3 DQN
```
loss = ( r + gamma * max_a' Q_target(s',a';w-) - Q(s,a;w) )^2
```
Two fixes, both essential:
1. **Experience replay** — sample minibatches uniformly from a large buffer. Breaks the temporal correlation of consecutive transitions (SGD assumes i.i.d.) and reuses each transition many times. Only valid off-policy.
2. **Target network** — compute the bootstrap target with a frozen copy `w−`, synced every C steps. Without it you regress toward a target that moves every update — a feedback loop that oscillates or diverges.

Plus: reward clipping, Huber loss, frame stacking (for POMDP-ness), ε annealing.

**The DQN improvement stack (Rainbow):**
```
Double DQN        a* = argmax Q_online(s',.) ; y = r + g Q_target(s', a*)
Dueling           Q(s,a) = V(s) + A(s,a) - mean_a A(s,a)
                  (learns V even when the action barely matters; the mean
                   subtraction fixes the unidentifiability of V and A)
Prioritized replay  sample with p ~ |TD error|^alpha, correct the induced bias
                  with importance weights (beta annealed to 1)
Multi-step        n-step returns instead of 1-step
Distributional    learn the DISTRIBUTION of returns (C51/QR-DQN), not just its mean
Noisy nets        learned parametric noise in the weights replaces eps-greedy
Rainbow           all six combined
```
Measured in the companion code (CartPole, 130 episodes, identical settings): vanilla DQN reaches 22.6 average return, **Double DQN 99.5**. The companion demo also notes how much noisier these runs are than the tabular ones — value-based deep RL is genuinely unstable, which is the entire justification for replay and target networks.

# PART 6 — POLICY GRADIENT METHODS

## 6.1 Why optimize the policy directly
- Naturally handles **continuous / high-dimensional action spaces** (a max over actions is intractable for value-based methods).
- Can learn **stochastic** optimal policies (needed in POMDPs and games).
- Smooth improvement: a small parameter change gives a small policy change, whereas ε-greedy on Q flips discontinuously.
- Cost: high variance, typically **on-policy** (sample-inefficient), and converges to a **local** optimum.

## 6.2 The policy gradient theorem
```
J(theta) = E_pi[ G_0 ]
grad J   = E_pi[ sum_t  grad log pi(a_t|s_t; theta) * Psi_t ]
```
Derivation rests on the **log-derivative (score function) trick**:
```
grad p = p * grad log p
  =>  grad E_p[f] = integral f grad p = integral p f grad log p = E_p[ f grad log p ]
```
This converts the gradient of an expectation into an expectation of a gradient, so it can be estimated from samples — with **no model** of the environment and **no differentiable reward**.

For a softmax policy the logit gradient is clean:
```
d log pi(a|s) / d z = onehot(a) - pi        (ascent direction: (onehot - pi) * Psi)
```

## 6.3 Baselines and the variance ladder
Subtracting any `b(s)` that does not depend on the action leaves the gradient **unbiased**:
```
E[ grad log pi(a|s) * b(s) ] = b(s) * grad sum_a pi(a|s) = b(s) * grad 1 = 0
```
but it can cut variance enormously. The natural choice is `b(s) = V(s)`, making the weight the **advantage**.
```
Psi = G_t                    REINFORCE          unbiased,   highest variance
Psi = G_t - V(s)             with baseline      unbiased,   lower variance
Psi = Q(s,a)                 actor-critic       biased,     lower
Psi = A(s,a)                 advantage AC       biased,     lower
Psi = r + gamma V(s') - V(s) TD error           biased,     lowest
Psi = GAE(gamma, lambda)     tunable dial between the last two
```

## 6.4 Actor-critic and GAE
```
actor   pi(a|s; theta)   updated by  grad log pi * A
critic  V(s; w)          updated by  regression onto the TD target

GAE:  A_t = sum_{l>=0} (gamma*lambda)^l delta_(t+l)
      delta_t = r_t + gamma V(s_(t+1)) - V(s_t)
      computed backwards in one pass:  A_t = delta_t + gamma*lambda*A_(t+1)
```
λ=0 gives the one-step TD advantage (low variance, high bias); λ=1 gives the Monte Carlo advantage (unbiased, high variance); λ≈0.95 is the standard compromise. **The critic is just a learned baseline** — actor-critic is the MC-vs-TD trade-off applied to policy gradients.

## 6.5 TRPO and PPO
**The problem:** vanilla policy gradient takes one step per batch. A step that is too large can collapse the policy, and there is no way back — the data for the new policy doesn't exist yet.

**TRPO** solves it with a hard KL trust region and second-order optimization (conjugate gradient + line search). Correct, but complex and expensive.

**PPO** gets nearly the same effect with a first-order clipped surrogate:
```
ratio r_t(theta) = pi_theta(a_t|s_t) / pi_old(a_t|s_t)
L_clip = E[ min( r_t A_t ,  clip(r_t, 1-eps, 1+eps) A_t ) ]
full objective = L_clip - c1 * value_loss + c2 * entropy
```
Read the `min` carefully:
- `A > 0` (good action): the objective stops improving once `r > 1+ε` → no incentive to push the probability arbitrarily high.
- `A < 0` (bad action): it stops once `r < 1−ε`.
- The `min` makes it a **pessimistic lower bound**, so the update is conservative in both directions.

Outside the band the objective is flat, so **its gradient is exactly zero** — which is what makes it safe to run several epochs of SGD over the same batch. That reuse is where PPO's sample efficiency over REINFORCE comes from.

Measured in the companion code (CartPole, max 200):

| Algorithm | First 20 eps | Last 20 eps | Greedy eval |
|---|---|---|---|
| REINFORCE (no baseline) | 46.8 | 197.2 | — |
| REINFORCE + baseline | 39.0 | 185.7 | 200.0 |
| Actor-Critic (A2C + GAE) | 45.2 | 196.2 | 200.0 |
| PPO (clipped surrogate) | 40.0 | 196.1 | 200.0 |

## 6.6 Continuous control
```
DDPG    deterministic actor + Q critic, off-policy, replay.
        Deterministic policy gradient: grad J = E[ grad_a Q(s,a) grad_theta mu(s) ]
        Brittle: sensitive to hyperparameters, overestimates Q.
TD3     three fixes to DDPG:
          1. TWIN critics, use the min -> combats overestimation
          2. DELAYED policy updates (update the actor less often than the critic)
          3. TARGET POLICY SMOOTHING (noise on the target action) -> smooths Q
SAC     MAXIMUM ENTROPY RL: maximize E[ sum r + alpha H(pi(.|s)) ]
        Stochastic actor, twin critics, automatic temperature tuning.
        The entropy term gives built-in, state-dependent exploration and makes
        it far more robust than DDPG. The default for continuous control.
```
For continuous actions a Gaussian policy is standard: the network outputs μ and log σ, and `log π(a|s)` is the Gaussian log-density (plus a tanh correction if actions are squashed into bounds).

# PART 7 — ADVANCED AND APPLIED

## 7.1 Model-based RL
```
Dyna            learn P, plan with simulated transitions (see Part 4.6)
MPC / CEM       replan every step by sampling action sequences in the model
MBPO            short model rollouts branched off real states, to bound
                compounding model error
World models    learn a latent dynamics model, train the policy inside it
                (Dreamer)
AlphaZero       MCTS + a learned value/policy net, exact simulator
MuZero          the same, but the model is LEARNED and only has to predict
                reward, value, and policy — not observations
```
**MCTS** in four steps: *selection* (descend by UCT = `Q + c·P·√N_parent/(1+N)`), *expansion*, *evaluation* (rollout or value net), *backup*.

Trade-off: model-based is far more sample-efficient but suffers **compounding model error** over long rollouts, and the final asymptotic performance is often lower than model-free.

## 7.2 Offline RL
Learn from a fixed dataset with **no interaction**. The core problem is **distributional shift**: the policy queries `Q(s,a)` for actions absent from the data, where the estimate is unconstrained and typically over-optimistic — and there is no way to collect a correction.
```
BC       behaviour cloning; supervised, ignores reward, caps out at the data
BCQ/BEAR constrain the policy to stay near the behaviour distribution
CQL      Conservative Q-Learning: penalize Q on out-of-distribution actions
IQL      never query unseen actions at all — expectile regression on the data
Decision Transformer  frame RL as return-conditioned sequence modelling
```

## 7.3 Multi-agent, hierarchy, and the rest
```
Multi-agent   the environment becomes NON-STATIONARY (other agents learn too).
              CTDE (centralized training, decentralized execution): MADDPG,
              QMIX. Self-play for zero-sum games.
Hierarchical  options / semi-MDPs; a manager picks sub-goals, workers execute.
              Attacks long-horizon credit assignment.
Meta-RL       learn to adapt fast (RL^2, MAML, PEARL)
Inverse RL    infer the reward from expert demonstrations; GAIL does this
              adversarially
Safe RL       constrained MDPs, Lagrangian methods, shielding, risk measures
```

## 7.4 RLHF — the RL most people now actually ship
```
1. SFT              supervised fine-tune on demonstrations
2. Reward model     train r_phi on human PAIRWISE PREFERENCES with the
                    Bradley-Terry loss:  -log sigma( r(chosen) - r(rejected) )
3. PPO              maximize  r_phi(x,y) - beta * KL( pi || pi_SFT )
                    The KL penalty is essential: without it the policy drifts
                    into gibberish that games the reward model (reward hacking).
DPO                 skips the reward model and the RL loop entirely, optimizing
                    the preference likelihood directly in closed form:
                    -log sigma( beta[ log pi(yw|x)/pi_ref(yw|x)
                                    - log pi(yl|x)/pi_ref(yl|x) ] )
Others              RLAIF (AI feedback), GRPO (group-relative, no value net),
                    best-of-n sampling, process supervision for reasoning
```
**Why PPO for LLMs?** Actions are tokens (huge discrete space), the reward arrives only at the end of a sequence, and stability matters more than sample efficiency because each rollout is expensive. PPO's trust region plus a KL anchor to the reference model is what keeps a 100B-parameter policy from collapsing.

## 7.5 Practical debugging checklist
```
1. Check the reward. Print the per-episode return. Sanity-check what a random
   policy and a hand-coded policy score — if random ~= trained, nothing learned.
2. Overfit a trivial version of the task first (1 state, 2 actions).
3. Verify the environment: are transitions/terminations correct? Is `done`
   being conflated with time-limit truncation? (Bootstrapping through a
   TIME LIMIT is correct; bootstrapping through a real terminal state is a bug.)
4. Normalize observations; clip or scale rewards.
5. Gamma: is the effective horizon 1/(1-gamma) long enough for the task?
6. Plot the value loss AND the entropy. Entropy collapsing to 0 early =
   premature convergence; entropy not falling at all = no learning.
7. Seeds: RL results vary enormously. Report a median over >=5 seeds.
   And make sure the agent's RNG is SEEDED DIFFERENTLY from the environment's —
   identical seeds give identical streams and silently correlate actions with
   outcomes. (This bug bit the gradient-bandit code in the companion file.)
8. For DQN: is the target network actually syncing? Is the replay buffer
   large enough and actually being sampled uniformly?
9. For PPO: check the KL between old and new policy per update; if it explodes
   the learning rate is too high.
```

# PART 8 — RAPID-FIRE Q&A

**Q: Explain RL in one sentence.** An agent learns a policy by interacting with an environment, choosing actions to maximize cumulative discounted reward, with only evaluative and often delayed feedback.

**Q: On-policy vs off-policy?** On-policy learns about the policy generating the data (SARSA, PPO); off-policy learns about a different target policy (Q-learning, DQN, SAC), which enables replay buffers and learning from logs, at the cost of stability.

**Q: Why does Q-learning need a max and SARSA doesn't?** Q-learning's target is the *optimal* value, so it bootstraps from the greedy action. SARSA's target is the value of the policy being followed, so it bootstraps from the action actually taken.

**Q: What is the deadly triad?** Function approximation + bootstrapping + off-policy training. Any two are safe; all three can diverge.

**Q: Why does DQN need a target network?** Without it the regression target moves every time you update the network, creating a feedback loop that oscillates or diverges. Freezing a copy for C steps makes it a stationary supervised problem.

**Q: Why a replay buffer?** Decorrelates consecutive samples (SGD assumes i.i.d.) and reuses each expensive transition many times. Only valid off-policy.

**Q: Why does a baseline not bias the policy gradient?** `E[∇log π · b(s)] = b(s)·∇Σ_a π(a|s) = b(s)·∇1 = 0`. It subtracts a zero-mean term, so the expectation is unchanged while the variance drops.

**Q: What does GAE's λ control?** The bias-variance trade-off in the advantage estimate: λ=0 is the one-step TD advantage (biased, low variance), λ=1 is Monte Carlo (unbiased, high variance).

**Q: Why does PPO clip?** To keep the updated policy close to the one that generated the data, so the same batch can be reused for several epochs without the policy collapsing. Outside the clip band the gradient is zero.

**Q: How do you choose gamma?** By the task's effective horizon, ≈1/(1−γ). γ=0.99 ≈ 100 steps. Too low is myopic; too high adds variance and slows convergence.

**Q: What is reward hacking?** The agent maximizes the literal reward in an unintended way (a boat racing in circles for pickups instead of finishing). Mitigations: better reward design, potential-based shaping, constraints, KL anchoring to a reference policy, human oversight.

**Q: Exploration methods beyond ε-greedy?** Optimistic initialization, UCB, Thompson sampling, Boltzmann, entropy bonuses, count-based/pseudo-count bonuses, curiosity (prediction error), noisy networks, Go-Explore.

**Q: Why is RL so sample-inefficient?** Evaluative (not instructive) feedback, delayed credit assignment, exploration cost, a non-stationary data distribution, and high-variance gradient estimates. Fixes: model-based methods, off-policy replay, demonstrations, transfer/pretraining, simulation.

**Q: Tabular Q-learning converges — does DQN?** No general guarantee. It sits inside the deadly triad; replay and target networks are empirical stabilizers, not proofs.

**Q: What's the difference between the value function and the reward?** Reward is the immediate, local signal defining the goal; value is the expected *cumulative discounted* reward from a state. Rewards are given, values are estimated — and estimating values well is basically the whole field.

**Q: Your agent's reward is flat at zero. Debug it.** Verify the reward is actually being emitted (log raw transitions); check it's reachable at all by a random policy; check γ and the episode length; check for a hard-exploration problem; check observation scaling; try a smaller version of the task.

**Q: When would you NOT use RL?** When you have labels (use supervised learning), when a simple controller or search works, when you can't simulate and real interaction is expensive or unsafe, or when you can't specify a reward that isn't gameable. RL is the tool of last resort for sequential decision-making, not a default.
